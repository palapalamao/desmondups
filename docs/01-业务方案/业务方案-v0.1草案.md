## 1. 领域结构性差异（UPS 车队 vs 商业建筑楼宇自控）——待补

- [ ] 供电连续性 = 生命级硬约束（断电即事故），区别于舒适型楼宇负载
- [ ] 设备异构：在线双变换 /  line-interactive / 模块化 N+1，能力矩阵差异大
- [ ] 关键指标口径：续航时间、SOC/SOH 基准、严重度分级——均需口径确认单
- [ ] 远程站点分散，通讯中断是常态而非异常

## 2. 失败模式清单（初稿）

| # | 失败模式 | 规避设计方向 |
|---|---|---|
| F1 | 平台展示数据与 UPS 实际状态不一致 → 运维误判 → 断电事故 | 数据时效显式标注；过期即标"参考值"；阈值可配 |
| F2 | 配置误下发（电池参数、阈值）→ 设备保护动作或损坏 | 守门引擎 fail-closed；下发前校验 + 版本化 + 全量留痕 |
| F3 | 告警风暴/重复确认 → 运维麻木，真告警被淹没 | 告警确认幂等；活动/已确认状态机清晰 |
| F4 | 通讯中断被当成"设备正常" | 通讯状态独立建模，缺口显式表达 |
| F5 | 口径争议（"续航怎么算"）导致指标不被信任 | 口径确认单多方会签，未会签标参考值 |

## 3. 设计铁律（草案，≤5 条，待决策层认可）

1. 保障优先：任何与供电安全冲突的功能让路。
2. 数据诚实：宁缺毋假，缺口与参考值显式标注。
3. 写操作守门：fail-closed，无证据即拒绝，否决留痕。
4. 历史不可改：版本化 + 红冲 + 幂等。
5. 只读优先集成：默认不写控制点。

### M1 设备总览 · 三段式详述（v0.2，微流程段 1 产出）

- **使用者**：运维值班员、车队管理员（经 FIN 授权的用户，按站点隔离可见范围）
- **解决的问题**：一屏掌握全部 UPS 单元的健康与供电状态，快速定位需要处置的设备；
  杜绝"列表看着正常、实际已断讯/告警"的误判（对应失败模式 F1/F4）
- **核心功能**：
  1. 授权范围内全部 UPS 单元列表：站点 / 名称 / 位置 / 通讯状态 / 供电模式 / 负载% / 电池 SOC / 当前最高严重度
  2. 筛选：站点、通讯状态、供电模式、严重度
  3. 分类统计徽标：按严重度计数（严重/警告/正常/断讯）
  4. 分页：50/100 每页
  5. 数据时效标注：每项附采集时间；超过采集周期未更新显式标注（缺口/参考值，红线 R3）
  6. 新严重风险提示：列表中出现新的严重级设备时给出可见提示（不自动刷新排序造成跳动——见 spec 决策 Q6）
  7. 点击行进入 M2 设备详情，返回时保留筛选与页码上下文
  8. 深链直达：`#/ups/overview`（SPA 路由，FIN 顶栏菜单传参）

### M2 设备详情 · 三段式详述（v0.4，微流程段 1 产出）

- **使用者**：运维值班员（处置单台异常的第一责任人）、维护工程师、车队管理员
- **解决的问题**：M1 回答"哪台"异常，M2 回答"这台到底怎么了"——供电链路/电池/负载/
  电力电子/环境/切换/预测维护全维度实况；杜绝"只看得见负载和 SOC 两个数、
  无法判断要不要去现场"（对应失败模式 F1）
- **核心功能**（视觉基线 = 原型详情页 8 面板，逐面板有生产取舍）：
  1. 头部：名称/站点/位置/拓扑/厂商/型号/序列号 + 供电模式 + 预估备电时长（全部带时效三态标注，R3）
  2. 电池健康：组电压/内阻（对基线对比告警）/温度/充电电流/容量趋势（内嵌窗与 M1 同规，D-07）/预测更换窗口（参考值口径）
  3. 负载与容量：负载条（分区变色）+ 负载趋势 + 需求备电时长 vs 当前预估
  4. 电力电子：逆变输出 V/Hz、输出 THD、整流器状态、风扇状态、电容健康度
  5. 环境：环境温度/湿度/空气质量/水浸（无传感器项按缺口显式标注，不裁剪面板）
  6. 切换与旁路：切换开关状态/维修旁路可用性/上次切换事件（事故复盘点位，points.xeto 已盘入）
  7. 预测性维护：风险项列表（全部标参考值口径 + 来源，R3）
  8. 告警与事件：列表 + 确认状态筛选 + 未确认计数——**只读，无确认按钮**（确认属 M4 写操作，必经守门引擎 R2）
  9. 深链 `#/ups/unit/{id}` + 返回总览保留筛选/页码（REQ-M1-07 回归）
  10. 不实现：原型"Simulate utility loss"演示按钮（D-04 演示与生产分离，裁剪留痕）

### M3 历史趋势 · 三段式详述（v0.5，微流程段 1 产出）

- **使用者**：运维值班员（事故复盘：市电中断时刻的电池/负载轨迹）、维护工程师（电池劣化/电容老化趋势判断）、车队管理员（容量规划依据）
- **解决的问题**：M1/M2 内嵌趋势只有 24 点滚动窗（240s，D-07），回答不了"过去 24 小时/7 天发生了什么"——市电中断那一刻 SOC 跌到多少、负载是否过载、电池温度是否异常；事后补测代价极高（points.xeto 盘入依据），必须可查 his（对应失败模式 F1/F4）
- **核心功能**（**原型缺口声明**：D-03 原型无独立历史页，本模块按原型视觉语言自建，取舍逐条留痕 A10 同规）：
  1. 深链 `#/ups/history/{id}?metric=&span=`，M2 详情页"全量历史"入口进入（M1 卡片不进，D-07 边界不破）
  2. 指标多选：电池 SOC / 负载 / 电池温度（points.xeto 已盘 his 点位：upsSocPct/upsLoadPct/upsBatteryTemp）
  3. 时间跨度预设档（1h/24h/7d/30d），粒度随跨度自适应（规则段 2 定死）
  4. 事件叠加：市电中断（upsInputFail）/ 切换成功（upsTransferOk）标记叠加在曲线上，事故复盘锚点
  5. 断讯时段曲线留白 + 缺口图例标注，禁止插值连线（R3 宁缺毋假）
  6. his 数据口径标注；参考值不混入历史曲线（R3）
  7. 返回 M2 详情保留上下文；只读纯查询视图，零写入口（R2 天然）
  8. 不实现（二期，spec 留痕）：多单元同图对比、自由起止区间、曲线导出
