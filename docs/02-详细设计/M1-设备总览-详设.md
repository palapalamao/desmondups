## 1. 信息架构（SPA 路由）

```
#/ups/overview ── M1 设备总览（本设计）
   ├─ 筛选栏：站点 / 通讯状态 / 供电模式 / 严重度
   ├─ 统计徽标条：严重 n · 警告 n · 正常 n · 断讯 n
   ├─ 卡片网格：每单元一张卡片（Q1）
   │    名称 / 站点 / 位置 / 模式圆点(Q4原型风) / 负载% / SOC / 最高严重度 / 采集时间
   │    断讯卡：整行/整卡"通讯中断"态（Q5）
   │    超时数据：标缺口/参考值（R3）
   ├─ 新风险横幅+徽标（Q6，不自动重排）
   └─ 分页：50/100（Q：50 默认）
```

- 点击卡片 → `#/ups/unit/{id}`（M2 路由占位，本次不实现）
- 返回：路由参数带回筛选/页码状态

## 2. 数据链路（零新增论证）

| 数据 | 通道 | 论证 |
|---|---|---|
| 单元清单/站点/位置 | Folio 读（upsUnit 记录，lib/ups 语义） | 领域记录，本就要建，非新增体系 |
| 负载%/SOC | hisRead 最近值（Q7） | 复用既有历史读通道——零新增 |
| 最高严重度 | FIN alarm 内核 severity 聚合（Q3） | 复用既有告警体系——零新增 |
| 通讯状态 | 连接器在线状态/点位新鲜度（hisRead 时间戳推导，待 U5 探测确认语义） | 复用——零新增 |
| 权限过滤 | FIN 用户授权范围（R1） | 内核能力——零新增 |

**零新增结论**：M1 后端接口零新增体系；仅新增 1 个 Axon 聚合函数
（暂名 `upsOverview()`，Lib.fan @Axon 注册），把上述既有通道的读数
按 M1 视图聚合。若 U4/U5 探测发现 hisRead/alarm 语义不满足，
新增须重新论证并回写本表。

## 3. 刷新与时效（Q2）

- 轮询周期 10s（可配置，写入扩展配置，默认 10）
- 每次轮询返回各单元采集时间戳；前端与服务端时差 > 2×周期 → 该项标"参考值"
- 无历史值 → 标"缺口"（R3）
