## 1. 守门引擎契约（gateAck 纯函数，四路拒绝按序短路）

| 序 | 校验 | 拒绝理由（明示文案） | 对应验收 |
|---|---|---|---|
| 1 | 告警存在性 | 告警不存在（可能已归档） | A20 |
| 2 | 状态=未确认 | 该告警已确认，不可重复操作（幂等保护） | A18/A20/A21 |
| 3 | 备注 trim ≥2 字 | 备注必填（至少 2 字）——留痕质量要求 | A19/A20 |
| 4 | 站点授权 ctx.allowedSites | 站点越权：不在授权范围 | A20/R1 |

- 返回 `{ok:true}` 或 `{ok:false, reason}`；reason 一律用户可读中文（否决留痕=铁律 3）
- 校验顺序即优先级；Mock ctx = `{allowedSites:null}`（全员，R1 留位）；Fin 侧由 FIN 会话注入

## 2. 状态机 + 审计事件契约

```jsonc
applyAck(units, auditLog, alarmKey, note, by, at) →
  先 gateAck；通过则 alarm.ack=true（alarm 对象仍恰四字段，TC-M2-逻辑-04 不破）
  并 push 审计事件（M6 消费）：
  { seq, type:"alarm.ack", alarmKey, unitId, siteId, severity, message, note, by, at }
```
- **单向**：已确认后再 applyAck → 序 2 拒绝，数据层零变更（UI 与数据双不可写，A21）
- **幂等**：双击/重试的第二次请求 = 已确认状态 → 序 2 拒绝，审计不重复（A18）
- auditLog 存 snapshot（内存）；seed 不含审计（运行时事件流）——M6 展示同一数组
- Mock operator 固定 "mock-operator"（无 FIN 会话，UI 明示口径）

## 3. 列表页交互（#/ups/alarms）

| 项 | 设计 |
|---|---|
| 聚合 | collectAlarms(units)：拍平所有 detail.alarms，key=unitId#index，含档案字段 |
| 筛选 | 站点/严重度/状态/单元关键字（深链参数同构）；未确认优先排序（Q5 延续 M2 规） |
| 统计徽标 | 活动 n · 已确认 n · 严重 n（筛选项激活高亮，M1 语言延续） |
| 行内确认 | 点\"确认\"展开该行（同时只展开一行）：备注 textarea + 提交/取消；提交走 submitAck |
| 已确认行 | 显示\"已确认 · by · at\"；无操作按钮（A21 UI 层） |
| 深链 | `#/ups/alarms?site=&sev=&state=&unit=`；非法参数同 M3 收敛语义 |
| M2 衔接 | 告警面板 h2 加\"去处理 →\"（fire goAlarms(unitId) → 带 unit 参数深链） |
| 轮询 | alarms 视图 poll 后重渲染列表（同 overview 分支） |

## 4. r2 检查边界（扫描范围划清）

- r2 现有：fan/前端 .js 禁写点位词（pointWrite 等）+ unit 模板段禁 ack 处理器（M2 详情区只读不破）
- M4 确认入口在 **alarms 视图段**（unit 段之外），handler 命名 submitAck——不在 r2 禁词表，不误伤
- 不扩 r2 扫描到 alarms 段：确认写入口是合法存在，扫掉它=破坏 M4 本身；语义守门由 gateAck 承担
